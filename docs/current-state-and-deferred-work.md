## 当前判断

在已审查代码和已有验证覆盖范围内，尚未发现需要立即回退当前分支、推翻架构或停止本地学习使用的重大缺陷。这不等于证明没有 bug；下文保留了具体恢复缺口、条件性安全风险和未验环境。

| 维度 | 评估 | 依据与边界 |
|---|---|---|
| 架构清晰度 | 良好，足以暂缓重构 | 公共机制、产品装配、玩法规则、表现和资源的所有权明确；关键业务可沿候选、提交、通知追踪 |
| 设计合理性 | 适合当前单进程本地工程 | 关键权益统一事务，普通动作合并检查点，内容按合适时机切换；没有要求所有产品行为进入公共框架 |
| 解耦程度 | 框架与纯规则较好，产品层仍处于渐进迁移状态 | 独立工程验证公共目录和业务端口；页面仍依赖 GameState、AB 与平台单例，不宣称全产品彻底解耦 |
| 可维护性 | 可用，但仍有集中复杂度 | 大页面、兼容字段投影、异步代次和双操作路径需要理解；应随具体问题局部整理，不按文件行数盲目重写 |
| 复用范围 | 已有有限而真实的证明 | 独立 Block 和窗口消费者可接入；不等于任意路径插件、所有游戏框架或同进程多产品平台 |
| 成熟度 | 本地工程验证较充分，生产环境尚未验收 | 完整自动检查、真实移动导出、原生 SDK、人工交互和生产网络是不同层次的证据 |

继续学习和阅读时无需先完成全部待办。仅当出现可复现问题、真实规模瓶颈、数据格式升级或明确发布需求时，重新评估对应项；不因“还能抽象”而继续扩大框架。

## 已知具体缺口与条件性风险

这些项目保留为未处理，不因暂缓重构而标记完成。代码路径结论主要来自静态审查，以下缺口本轮没有新增故障复现测试。

### R1：冷启动待领奖励缺少通用后续重试

**现状与影响：** [AwardManager](../products/meowdoku/app/features/award/award_manager.gd) 在 `_ready()` 中仅执行一次 `_sweep_in_flight_on_cold_start()`；`_persist_award()` 写失败后保留持久记录并报错，没有通用再次扫描调度。若此时暂时写失败、随后存储恢复，待领项可能等到下次重启或特定业务重新触发才兑现。这是恢复及时性缺口，不是已证明奖励永久丢失。广告管理器已有的同进程重试不能概括为所有冷启动待领项都有重试。

**重新处理条件：** 实际遇到补发滞留，或下一次修改奖励恢复流程。

**建议及验收：** 有限退避、回前台重试，成功停止、清档取消；验证短暂写失败后无需重启即可到账，并且不重复发奖。

### R2：错误提示与实际恢复办法不完全对应

**现状与影响：** [Launcher](../products/meowdoku/app/bootstrap/launcher.gd) 对存档失败统一建议重启；未知 schema 或永久损坏不会因重启自动解决。[BaseGamePage](../products/meowdoku/gameplay/presentation/main/view/base_game_page.gd) 的 `_report_business_failure()` 除内容标记外统一提示保存失败，部分无合法题目或搭盘失败也会进入此分支。

**重新处理条件：** 修改故障界面、遇到真实坏档或准备让其他人独立使用。

**建议及验收：** 区分临时读写失败、版本不兼容、内容失败与无法恢复的损坏；提示对应动作并保留原文件。未知档不得自动清空或当新用户覆盖，重建数据应是单独明确选择。

### R3：调试 HTTP 在可达网络上存在未鉴权风险

**现状与影响：** [DebugApiServer](../products/meowdoku/app/diagnostics/api/debug_api_server.gd) 监听 `0.0.0.0`，按路径直接分发，无鉴权，包含状态修改、崩溃和卡顿测试接口。[入口管理器](../products/meowdoku/app/diagnostics/debug_api_server_manager.gd) 仅在 debug 构建启动服务；这是旧实现延续的开发环境风险，不是本次新增，也不是已证明正式包暴露端口。

**重新处理条件：** 在不可信局域网运行可达的 debug 服务、需要远程调试，或分发调试包。在这些条件下应优先处理，不能按一般长期整理项无限推迟；是否可达还取决于主机网络与防火墙。

**建议及验收：** 默认仅监听本机，远程访问显式开启并使用会话凭证；验证未授权请求不能触发业务或诊断动作，正式构建不监听。

## 可随需求处理的维护与规模事项

| 编号 | 当前事实或风险 | 重新评估条件 | 处理方向与验收要点 |
|---|---|---|---|
| M1 兼容接口 | GameState 部分 setter 仍返回 void，调用者不能直接取得保存结果；权威状态仍有失败回投影 | 修改带 UI 或平台副作用的调用 | 逐个返回明确结果，失败不继续成功副作用；不一次重写全部 setter |
| M2 统计重试 | 合并统计的一次性 timer 超时写失败后保留 dirty，但不自动重新启动；下一事件、后台或其他提交可能保存 | 统计变成必须持久的数据，或实际发现遗漏 | 区分可丢统计与关键状态，明确重试与终止策略；不声称所有写失败都自动持续重试 |
| M3 双操作路径 | 普通输入修改活模型后保存检查点，关键消费经过事务会话；`sync_runtime()` 是兼容接缝 | 修改输入、道具、恢复链路 | 保持唯一活模型，验证普通操作→消费→失败→重启组合；不强制每格动画同步落盘 |
| M4 大页面与投影 | BaseGamePage、GamePage、GameState 仍集中大量职责和全局依赖 | 某职责频繁改动或重复引发错误 | 产品内部按稳定职责局部拆分；先减少重复决策与状态副本，再考虑抽公共接口 |
| M5 整档同步成本 | 每次核心提交涉及复制、校验、双槽读取、加密写和回读；成本随状态大小增加 | 实际卡顿、存档增长或目标设备变化 | 测真实大小、写频率与 p95/p99；先减少重复提交，再决定分区或调度，保留成功后发布语义 |
| M6 去重记录增长 | `claims` 持续追加稳定业务凭证，没有常规裁剪 | 长期数据达到可测量成本 | 按业务水位或可拒绝旧请求的窗口压缩；不能简单删最旧记录，必须验证旧请求不会再次领奖 |
| M7 内容与资源成本 | 网络等待异步，但安装/重验包含同步哈希、复制和产品验证；窗口与原资源回退缓存会驻留 | 启用大内容、长会话内存增长或首开变慢 | 测安装/冷启动/页面/驻留峰值；按证据减少重复工作或增加可控缓存策略，不直接认定泄漏 |
| M8 存档演进 | 核心 schema 当前为 1，不兼容版本安全拒绝；旧档只单向导入，不双写 | 第一次修改存档结构，或需要程序降级 | 增加显式版本转换、失败保留、幂等迁移和回退流程；切回 main 不等于最新进度可无损回退 |
| M9 合同可读性 | 端口依赖方法约定，结果/快照大量使用 Dictionary | 稳定跨层接口频繁出现字段或方法误用 | 优先补构造、校验和合同说明；不把所有局部字典都改成新类或引入服务容器 |
| M10 持续验证 | 仓库有本地入口，尚无仓库内 CI 配置；部分子过程诊断分类不足，退出告警仍保留 | 多人协作、持续改动或发布前 | 固定 Spine 引擎环境，分层运行快速/相关/完整检查；追踪诊断，不以扩大例外名单替代修复 |
| M11 教学注释 | 部分源码注释仍按旧 endgame.cfg/streak.cfg 描述实际落盘；恢复身份报告描述历史版本 | 阅读相应模块或单独授权注释整理 | 按“现核心分区、旧迁移来源、运行时字段”解释，维护原版与重构版两条阅读路线；本次未修改源码注释 |

[存储性能记录](validation/storage-performance.json)的桌面样本为每档 12 次：约 14 KB / 229 KB / 918 KB 的提交 p95 约 1.29 / 15.11 / 60.56 ms。它提示规模风险，但没有旧版同条件对照，也不是手机预算，不能据此断言当前正常游戏已经卡顿。

M1–M3 的接口与提交语义见[本地业务](local-business.md)；M4、M9 的边界见[框架使用指南](framework-usage.md)；M7 的阶段与限制见[内容交付](content-delivery.md)。

## 仅在扩展使用范围前必须完成的事项

| 编号 | 触发条件 | 必须确认的内容 |
|---|---|---|
| E1 原生激励广告 | 接入真实广告 SDK | 新桥提供逐次 show_id 合同，验证乱序、重复、关闭、后台与进程终止；旧桥激励不可用是当前兼容边界。若承诺跨进程权益可靠恢复，需要持久凭证，内存重试不能替代 |
| E2 移动发布与交互 | 导出或分发正式应用 | 匹配模板的实际 release 包、真机触控/安全区/动画/语言排版、后台恢复、最终包资源与调试能力；模拟构建谓词和桌面 PCK 不代替此验收 |
| E3 生产内容更新 | 配置实际公钥与更新渠道 | 生产 CDN/TLS、签名密钥轮换与失陷恢复、版本回退演练、下载与安装峰值空间；默认空配置未开启生产更新 |
| E4 内容制作易用性 | 持续发布多份远端内容 | 发布前展示覆盖/回落内置/需重启/运行时兼容的差异；JSON 不自动继承上一个远端版本。频道防回放基于本地已保存水位，不提供重装后历史水位或服务器权威 |
| E5 更大并发或信任范围 | 多进程写档、联网权益或反作弊成为真实需求 | 重新设计相应协议与信任边界；本地加密口令、revision 和单进程事务不能直接当作服务器权威或防篡改体系 |

这些条件尚未出现时，不需要为了“预防未来”提前构建云存档、服务器、通用产品注册平台、完整运营后台或通用迁移框架。
