## 方法与不变量

1. 固定三个提交与开始时的工作区指纹；原有未提交文档独立保留。实现先在隔离副本完成，验证后核对漂移再应用。
2. 对三棵树逐文件分类：新建、上游修改、仅重构修改、两边修改、上游删除、路径迁移、二进制资源、历史证据。每个上游文件必须有目标或明确解释，目标碰撞必须为零。
3. 路径和纯资源变更自动转换；业务冲突逐函数审核。不得使用整批 ours/theirs 决议，不得以启动通过代替功能迁移。
4. 保留 class_name、场景节点、信号、动画轨道、UID、实验默认值、特殊关语义、商店协议和资源内容。需要主动修复的缺陷单独记录并测试，不夹带难度或收费规则调整。
5. 公共层继续不引用产品；纯 domain 不读 Autoload、文件或页面。新版策略属于产品 application，不能因文件变多而塞进通用框架。
6. 业务候选隔离：选题、奖励、结算、云合并等先计算候选，提交成功后发布；存档 schema 显式升级，未知 schema 仍拒绝，旧文件只读导入，不双写新旧存档。
7. 每次异步完成重新核对所属页面、账号、日期或任务轮次；对局冻结规则、策略和题源，迟到结果不得影响新状态。
8. 测试使用独立数据目录和网络替身，不访问真实玩家档、商店或生产接口。真实服务与原生 SDK 未验证不能写成通过。
9. 原包保真清单保留历史含义；迁移后源码指纹、行为修复和最终配置另建证据，不能重写原报告冒充最终验收。
