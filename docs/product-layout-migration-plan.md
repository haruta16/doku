# Meowdoku 产品归属迁移计划

日期：2026-10-29。目标是让目录直接表达产品所有权，让公共框架的接入范围可以辨认；本次不建设多产品运行平台。

## 最终归属

```text
scripts/framework/              公共机制，保持已有固定接入路径
scripts/examples/block/         独立接入示例，含 domain/ 验证规则
products/meowdoku/
  app/                          启动、存档、服务、平台、产品功能与 UI 装配
  gameplay/                     本产品的规则、选题、内容合同与表现
  editor/                       本产品的题目编辑工具
  assets/                       本产品美术、音频、字体、翻译、内置配置与题库
  launcher.tscn                 本产品启动场景
project.godot                   当前 Meowdoku Godot 工程入口
export_presets.cfg              当前 Meowdoku 导出配置
addons/                        保留插件安装约定位置，逐项区分通用工具与产品适配
tools/                         仓库级验证与内容制作工具
```

`gameplay/domain` 继续保持纯规则边界，但归属本产品；以后出现真实跨产品复用需求再提取。根工程配置和插件不因仍在根目录而成为公共框架。`icudt_godot.dat` 是引擎数据，保留原位置。

## 不变量

- 只调整所有权与资源路径；产品 GDScript 的可执行正文除资源地址外保持一致。
- 保留 class_name、脚本 UID、场景 UID、资源 UID、节点名称、信号、动画轨道和导入参数。
- 原始图片、字体、音频、Spine 源文件、加密题库和翻译二进制保持字节相同。
- 不修改玩家存档路径、schema、字段、收费规则、奖励身份或关卡策略。
- 不修改内容 product/runtime、逻辑 ID、媒体槽位与 `res://content/<product>/<release>/` 包内命名空间。
- 不改写 `.autoconverted`、原始场景身份清单和历史验收报告；原身份到当前文件由显式映射记录。
- 公共框架不依赖产品/示例；产品不依赖其他产品或示例；示例不依赖产品；纯规则不依赖表现与产品服务。

## 执行顺序与门槛

1. **冻结基线。** 记录迁移前全部纳入范围文件的 SHA-256；保留只读基线副本，不使用 Git reset 或覆盖原有未提交修改。
2. **在临时副本迁移。** 使用完整且无目标碰撞的文件映射，保留 UID；更新场景、启动、资源绑定、插件、导出过滤和恢复映射。二进制资源不做字符串替换。
3. **修复工具与说明。** 隔离验证复制和存档重定向覆盖 products；更新独立示例和内容工具的复制清单；公共依赖门禁采用真实产品边界。
4. **冷导入与资源检查。** 在隔离工程重新导入；验证二进制动画的参数和依赖、UID 的新路径、场景与翻译加载、导出资源过滤。失败先定位，不放宽业务校验。
5. **完整相关验收。** 运行自包含完整回归、恢复身份、启动、公共目录/UI/Block/业务独立验证、Python 门禁，以及内容交付、产品发布、Spine 与 PCK 专项。
6. **应用到工作区。** 先确认工作区自基线后没有外部改动；按已验证的映射与文件差异应用。删除的只能是本清单中已迁移且内容对应的旧文件，不保留兼容空壳或旧实现副本。
7. **最终复核。** 对照已测副本核验最终文件指纹，检查旧活动引用、UID、导出过滤、架构和当前文档链接；归档结果与未覆盖环境。

## 收尾标准

所有已迁移文件有明确归宿；所有活动引用指向现位置；保留历史身份的文件与报告明确标注用途。每个失败都必须归因到真实实现、工具/夹具或外部环境；旧的已知退出资源诊断继续保留，不能将它们写成无告警。

跨平台移动包、原生 SDK、生产 CDN 和人工视觉仅在实际具备环境时验证。本次路径迁移不会把桌面或 PCK 验收改称移动发布验收。

## 执行结果

上述七步已执行。1,552 个文件完成归属迁移；应用前核对 2,267 个基线文件，没有发现工作区外部改动；应用后的 2,270 个文件与已验证副本一致。随后仅更新本文及验收记录。

运行代码、场景和资源的差异有规范化比对；UID 与原始资产另做字节核对。冷导入所需缓存由隔离工程生成后应用，没有启动真实工作区的产品 Autoload 或读写玩家存档。引擎首轮导入的主题字体顺序问题在未迁移基线同样复现，工具采用明确的临时预导入与原配置恢复，不忽略缺失资源错误。

验证步骤、指纹、历史资源诊断与环境边界见 [最终验收报告](validation/product-layout-migration-report.json)。
