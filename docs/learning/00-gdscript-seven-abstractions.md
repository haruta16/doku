# GDScript 七种根基抽象

> 编程语言里的每一个词，都在扮演一个**角色**。同一角色可以出现很多次，但角色**种类**是有限的。GDScript 里有 7 种。
>
> 理解它的关键不是背颜色，而是理解**每种抽象本质上是什么**。

---

## 这个框架和编译原理的关系

编译原理里，代码先被**词法分析**切成 Token，标准分类是六种：

> Keywords / Identifiers / Literals / Operators / Delimiters / Comments

而这套七抽象框架是**给读代码的人用的**，不是给编译器用的。它和标准分类有两处刻意不同：

| 区别 | 为什么 |
|---|---|
| 「型」被提升为独立顶层抽象 | 标准分类里 `Vector2` 只是一个标识符——它和变量名是同一类 token。但在人眼里，`var x: Vector2` 的 `Vector2` 和 `x` 干活完全不同。我选择让这个区别可见。 |
| 「运算符」和「分隔符」合并为「符」 | 对初学阶段，区分 `+` 和 `(` 的差异不如先理解「它们都不是名也不是値」重要。子类里会分开。 |

> 下面每个抽象里会标注「对应标准分类的什么」。

## 概览

```
                    你的 .gd 文件
                         │
        ┌────────────────┼──────────────────┐
        │                │                  │
      令 (关键字)       名 (标识符)         値 (字面量)
      结构骨架          指向某物的标签      数据本身
        │                │                  │
   ┌────┴────┐     ┌─────┼──────┐     ┌────┼────┐
   │声明令   │     │变量名 函数名 │     │数字 字符串│
   │流程令   │     │类型名 信号名 │     │布尔 null │
   │逻辑令   │     │内置函数名    │     │枚举常量  │
   └─────────┘     │特殊名(self) │     └─────────┘
        │          └─────┴──────┘
   ┌────┴────┐
   │注 @...  │   型 (类型标注)     符 (符号)
   │元数据   │   形状约束     ┌──运算符(+ - = ==…)
   └─────────┘              └──分隔符(: . $ ()…)
        │
   ┌────┴────┐
   │释 # ... │
   │人类笔记 │
   └─────────┘
```

## VSCode 颜色 → 抽象

| VSCode 颜色 | 对应的根基抽象 | 为什么这个颜色 |
|---|---|---|
| **紫色** | 令（所有关键字） | GDScript 的骨架，是语言内置的，不是你写的 |
| **青色** | 型（类型标注） | 所有类型的名字都用这个色，内建或自定义 |
| **黄色** | 名（函数名—定义和调用处） | 可执行的东西需要醒目 |
| **白色** | 名（变量名—定义和调用处） | 最常用，默认色，不喧宾夺主 |
| **橙色** | 値（数字 + 字符串 + 枚举值） | 数据本身用暖色，和「逻辑结构」（紫）形成对比 |
| **粉色** | 注（@export, @onready） | 元数据用特殊色：「这不是常规执行逻辑」 |
| **灰色** | 释（# 注释） | 降低存在感：「不重要，跳过没关系」 |

## 🧭 使用指南：如何用这套框架读代码

当你面对一行不理解的代码时，不要猜。**先把每个词按七种角色切开。**

```
例：@export var damage: int = 5

切法：
@export  → 注（元数据，给编辑器看的）
var      → 令（我要创建盒子）
damage   → 名（盒子叫 damage）
:        → 符（下面是类型标注）
int      → 型（盒子里只能装整数）
=        → 符（把右边的值装进去）
5        → 値（数据本身：数字 5）
```

**切完之后，卡住你的那个词是什么角色？**

| 你卡在 | 去做什么 |
|---|---|
| 令 | 查这个关键字的语义（GDScript 关键字就那几十个） |
| 名 | 追踪它指向什么——变量？函数？信号？在哪定义的？ |
| 型 | 查这个类型的定义——它有什么属性和方法？ |
| 値 | 它就是数据本身，不需要追查 |
| 注 | 查这个注解的文档——它改变了编辑器的什么行为？ |
| 符 | 查这个符号的语义——运算？分隔？别跟其他符号搞混 |
| 释 | 那是人类写的笔记，跳过不影响执行 |

**核心心法**：分类本身帮你定位"卡在哪里"。不是猜，是分类→定位→查询。

## 抽象一：値（Value）— 「数据本身」

> 对应标准分类：**Literals**（字面量）+ **Constants**（常量）
>
> **本质**：一个具体的、不可再分解的数据。它就**是**那个东西，不是指向别处的标签。

| 子类 | 例子（项目里） | 怎么判断 |
|---|---|---|
| **数字** | `1` `50` `0.3` `5.0` | 直接写的数字 |
| **字符串** | `"walk_left"` `"idle"` | 双引号包着 |
| **布尔** | `true` `false` | 真或假，只有两个 |
| **空** | `null` | 「什么都没有」 |
| **枚举成员** | `DataTypes.Tools.AxeWood` `DataTypes.Tools.None` | `enum { }` 块内定义的、有名字的固定值 |
| **类常量** | `Vector2.LEFT` `Vector2.DOWN` `Vector2.ZERO` | 类里用 `const` 定义的固定值，也以 `类型名.成员名` 形式访问 |

> `true` / `false` / `null` 在 VSCode 里是紫色（关键字色），但**语义上它们是値**——它们就是数据本身，不是指令。这是语法高亮和语义之间的一个已知偏差。

**为什么「値」是独立抽象？** 因为値不依赖任何其他东西存在。`50` 就是 50，你不需要解释、查找、引用。它直接**是**。

```
speed = 50
──┬──   ─┬─
  │      └─ 値（数据本身：数字 50）
  └─ 名（一个标签：speed）
```

## 抽象二：名（Name / Identifier）— 「指向某物的标签」

> 对应标准分类：**Identifiers**（标识符）
>
> **本质**：你给某个东西取的**名字**。名字本身不是那个东西——它是指向那东西的**引用**。

### 属性一：种类 — 「指向什么」

名可以指向不同类型的东西。这是名最基础的属性。

#### 子类总览

```
     名
     │
     ├── 变量名        → 指向一个「装数据的盒子」
     ├── 函数名        → 指向一段「可执行的指令」
     ├── 类型名        → 指向一个「蓝图」
     ├── 信号名        → 指向一个「事件频道」
     ├── 内置函数名     → 引擎提供的函数（print, preload…）
     └── 特殊名         → 有固定含义的内置标识符（self）
```

| 子类 | 指向的是什么 | 能对它做什么 | 例子 |
| --- | --- | --- | --- |
| 变量名 | 装数据的盒子 | 读、写 | `player_direction` `speed` `current_damage` |
| 函数名（你定义的） | 一段指令 | 调用执行 | `movement_input()` `apply_damage()` `_on_enter()` |
| 函数名（引擎内置） | 引擎提供的指令 | 调用执行 | `print()` `preload()` `get_node()` `emit_signal()` |
| 类型名 | 蓝图 | 做类型标注、继承 | `HitComponent` `NodeStateMachine` |
| 信号名 | 事件频道 | emit 发信号、connect 订阅 | `hurt` `transition` `max_damage_reached` |
| 特殊名 | 当前实例本身 | 引用自己 | `self` |

#### 用户定义 vs 引擎内置

同一个函数调用 `play("walk_left")` 和 `movement_input()`——两者都是「名（函数名）→ 指向一段指令」。区别只在于：

| | 谁定义的 | 在哪定义的 |
|---|---|---|
| `movement_input` | 你 | [game_input_event.gd](../../scripts/game_input_event.gd) |
| `play` | Godot 引擎 | AnimatedSprite2D 类 |
| `print` | Godot 引擎 | 全局内置 |

分类上它们都是**名（函数名）**——使用方式完全一样：`名字()`。

#### 在代码里分辨六种名

```gdscript
# 变量名 — 指向盒子
var player_direction: Vector2
#   ────────┬───────
#           └─ 变量名

# 函数名（你定义的）— 指向指令
func movement_input() -> Vector2:
#   ───────┬───────
#          └─ 函数名

# 函数名（引擎内置）— 指向引擎提供的指令
print("hello")
# ──┬─
#   └─ 内置函数名

# 类型名 — 指向蓝图
class_name HitComponent
#         ──────┬──────
#               └─ 类型名

# 信号名 — 指向事件频道
signal hurt
#      ──┬─
#        └─ 信号名

# 特殊名 — 指自己
self.position = Vector2.ZERO
# ──┬─
#   └─ 特殊名：当前实例
```

### 属性二：作用域 — 「在哪能被看见」

同一个 `var` 关键字声明的名，放在不同位置，能看见它的范围完全不同。

| 声明位置 | 修饰令 | 作用域 | 访问方式 | 项目例子 |
|---|---|---|---|---|
| 函数内部 | 无 | **局部**：只在当前 `func` 的缩进代码块内 | 直接写名字 | `walk_state.gd` 里的 `var direction` |
| 脚本顶层 | 无 | **实例**：属于每个实例，各自独立 | `实例.名` | `player.player_direction` |
| 脚本顶层 | `static` | **类级**：挂在蓝图上，全局共享 | `类名.名` | `GameInputEvents.direction` |

```gdscript
# walk_state.gd
func _on_physics_process(_delta: float) -> void:
    var direction = GameInputEvents.movement_input()
    #   ───┬───
    #   局部名：只在 _on_physics_process 的缩进代码块内可见
    #   出了这个函数，direction 这个名字就不存在了

# player.gd（脚本顶层，无 static）
var player_direction: Vector2
#   ────────┬───────
#   实例名：每个 player 实例有自己的 player_direction 盒子
#   外部通过 player.player_direction 访问

# game_input_event.gd（脚本顶层，有 static）
static var direction: Vector2
#          ───┬───
#   类级名：整个程序只有这一个 direction 盒子
#   外部通过 GameInputEvents.direction 访问
```

**为什么需要三种作用域？** 因为数据的生命周期不同。`direction`（局部）只在一次移动计算中有意义，用完就扔。`player_direction`（实例）需要活到下一次 Idle 状态读取。`GameInputEvents.direction`（类级）需要被所有状态共享——键盘方向是全局的，只有一份。

> 读代码时，如果看到 `实例.名` 或 `类名.名` 的形式：`.` 左边的部分决定了你需要在哪个脚本里找这个名的定义。

### 属性三：赋值语义 — 「拷贝还是共享」

当你写 `var a = b` 时，`a` 盒子里装的是什么？这取决于 `b` 的**型**。

| 型 | 赋值语义 | `var a = b` 的行为 | 改 a 影响 b？ |
|---|---|---|---|
| `int` `float` `bool` `String` `Vector2` `Color` 等基础型 | **值拷贝** | a 的盒子里有 b 的值的一个独立副本 | ❌ 互不影响 |
| `Node` `Resource` 所有自定义类 | **引用** | a 的盒子里有 b 的**内存地址**，指向同一个对象 | ✅ 改属性互相影响 |
| `Array` `Dictionary` | **引用** | 同上 | ✅ 改内容互相影响 |

```gdscript
# 值拷贝 — 互不影响
var a: Vector2 = Vector2.LEFT          # a = (-1, 0)
var b: Vector2 = a                     # b = (-1, 0)，是副本
b.x = 99                               # b = (99, 0)，但 a 还是 (-1, 0)

# 引用 — 共享同一个对象
@onready var h: HitComponent = $HitComponent
var ref = h                            # ref 和 h 指向同一个 HitComponent 实例
ref.current_tool = DataTypes.Tools.AxeWood
# h.current_tool 也变成 AxeWood —— 同一个东西，两个名字
```

**为什么这是名的属性？** 型决定了语义（值 vs 引用），但你观察到的行为发生在**名**上——两个名共享同一个对象，改一个名的属性影响另一个名。这是名与名之间的关系。

> 读代码时，先看 `:` 后面的型：基础型 = 拷贝安全，Node/Resource/自定义类 = 共享引用。

### 属性四：通信方向 — 「向下调函数，向上发信号」

在 Godot 的节点树里，名（函数名）和名（信号名）有天然的通信分工，方向相反。

| 方向 | 用的名 | 模式 | 为什么 |
|---|---|---|---|
| **向下**（父→子） | 名（函数名） | `$子节点.函数名()` | 父持有子的引用，知道子有什么函数——定向调用 |
| **向上**（子→父） | 名（信号名） | `信号名.emit()` → 父 `.connect()` | 子不依赖父是谁，信号是广播——谁听都行 |

```gdscript
# 向下通信 — 函数名：父主动调用子
# large_tree.gd → damage_component.gd
$DamageComponent.apply_damage(1)
#─────┬──────  ─────┬─────
#      │             └─ 名（函数名）：父知道子有这个函数 → 定向调用
#      └─ 名（变量名）：父持有子的引用

# 向上通信 — 信号名：子广播，父订阅
# hurt_component.gd（子）：
hurt.emit(hit_damage)
#─┬─  ─┬─
# │     └─ 名（方法名：emit，触发广播）
# └─ 名（信号名：hurt，广播频道）

# large_tree.gd（父）：
hurt_component.hurt.connect(on_hurt)
#─────┬──────  ──┬─  ───┬───  ───┬──
#      │          │       │        └─ 名（函数名：回调——收到信号后执行）
#      │          │       └─ 名（方法名：connect，订阅频道）
#      │          └─ 名（信号名：hurt，监听这个频道）
#      └─ 名（变量名）：子节点引用
```

**本质**：函数名是**定向**的——你调它时知道它在哪。信号名是**广播**的——发送者不依赖接收者，接收者自己选择要不要订阅。Godot 的节点树天然支持这个分工：上层知道下层结构（能调子节点的函数），下层不应该绑定上层结构（所以用信号广播）。

> 下次不确定节点间该怎么沟通时，问自己：调用方持有对方的引用吗？有 → 直接调函数名。不知道对方是谁 → 用信号名广播。

## 抽象三：型（Type）— 「形状的描述」

> 对应标准分类：**不是独立的词法类别**。在编译原理里，类型名只是标识符出现在特定位置（`:` 或 `->` 后面）。这里为了可读性提升为独立顶层抽象。
>
> **本质**：描述一类值**长什么样、能做什么**。型不是数据，型是**对数据的约束**。

```gdscript
var direction: Vector2
#              ───┬───
#                 └─ 型：direction 这个盒子只能装「有 x 和 y 两个分量的东西」
```

型出现在两个位置：
- `:` 后面：`var speed: int`（这个盒子只能装整数）
- `->` 后面：`-> Vector2`（这个函数还回来的东西必须是 Vector2）

### 型的子类

| 子类 | 例子 | 谁定义的 |
|---|---|---|
| 内建基本型 | `int` `float` `bool` `String` `void` | GDScript 语言 |
| 内建复杂型 | `Vector2` `Dictionary` `Array` | Godot 引擎 |
| 引擎节点型 | `CharacterBody2D` `Area2D` `AnimatedSprite2D` `Node2D` `Node` | Godot 引擎 |
| 你定义的型 | `HitComponent` `NodeStateMachine` `DataTypes` `player` | 你（通过 `class_name`） |

> `void` 也是型——它是「无返回值」的类型，和 `int` 一样出现在 `->` 后面：`func foo() -> void:`。

### 型 vs 名 — 同一个词出现在不同位置

```gdscript
class_name HitComponent    ← HitComponent 是 名（你在给蓝图贴标签）
var h: HitComponent        ← HitComponent 是 型（你在描述 h 的形状）
```

**判定方式**：出现在 `:` 或 `->` 后面的时候，它扮演「型」的角色。其他位置是「名」。

## 抽象四：令（Instruction / Keyword）— 「结构的骨架」

> 对应标准分类：**Keywords**（关键字）
>
> **本质**：告诉编译器和运行环境「这里在做什么结构操作」。令不存数据、不指向数据——它是**操作的标识**。

### 声明令 — 「我要创建新东西」

```gdscript
var          ← 「下面要创建一个可变数据盒子」
const        ← 「下面要创建一个不可变数据盒子（常量）」
func         ← 「下面要定义一段指令」
class_name   ← 「下面要给这个蓝图起名字」
class        ← 「下面要定义一个内部类」
extends      ← 「这个蓝图的基座是...」
signal       ← 「下面要创建一个广播频道」
enum         ← 「下面要定义一组有关联的固定值」
```

> `const` 和 `var` 的区别：`const` 创建的盒子一旦装了东西就不能再换——它是常量。`var` 创建的盒子随时可以换内容。

### 修饰令 — 「改变声明的属性」

```gdscript
static       ← 「这个东西挂在蓝图上，不挂在实例上」
```

修饰令不单独使用——它修饰声明令。`static var` = 蓝图级别的变量，`static func` = 蓝图级别的函数。详见 [基础概念](01-basic-concepts.md) 里 static 一节。

### 流程令 — 「控制执行的路线」

```gdscript
if / elif / else   ← 「条件分叉」
return             ← 「执行到这里停下，把后面的东西还回去」
pass               ← 「这里故意什么都不做（占位符）」
for / while        ← 「重复执行」
match              ← 「多路分叉」
break / continue   ← 「跳出循环 / 跳过本次循环」
```

### 转换令 — 「改变型」

```gdscript
as                 ← 「把它当成这个型来用」（如 area as HitComponent）
```

### 逻辑令 — 「条件组合」

```gdscript
and / or / not     ← 「且 / 或 / 非」
is                 ← 「它的型是 X 吗？」（如 child is NodeState）
in                 ← 「这个东西在里面吗？」
```

### 异步令

```gdscript
await              ← 「先等那边的事做完，再继续往下走」
```

### 令 vs 名 — 同一行里的三者

```
var direction: Vector2
──┬─ ────┬───  ───┬───
  │      │        └─ 型（形状描述）
  │      └─ 名（你给盒子起的标签）
  └─ 令（创建盒子的指令）
```

- `var` 是**动作**：「我要创建！」
- `direction` 是**标签**：「这个东西以后叫 direction」
- `Vector2` 是**约束**：「这个盒子只能装 Vector2」

## 抽象五：注（Annotation）— 「给引擎看的元数据」

> 对应标准分类：GDScript 特有的 **ANNOTATION** token（不属于 Keywords）
>
> **本质**：写给**编辑器、编译器和引擎**的额外说明。它通常不表达普通业务逻辑，但可能改变变量暴露、赋值时机、脚本运行方式等行为。

```gdscript
@export          ← 「把这个变量暴露到 Inspector 面板，并允许场景保存覆盖值」
@onready         ← 「等节点进入场景树并 ready 后再给变量赋值」
@warning_ignore  ← 「这条警告我知情，别报了」
```

`@` 符号本身就是一个信号：「接下来的内容不是普通语句，是元数据/修饰信息。」

**为什么「注」是独立抽象？** 因为它不像 `if` / `return` 那样直接写一段执行流程，也不像变量名那样指向数据；它是在改变引擎或编辑器如何对待后面的声明。比如删掉 `@export`，变量仍然存在，但 Inspector 里不再暴露这个槽，场景文件也不能用同样方式覆盖它。

> 在 GDScript 编译器里，注解是一个独立的 `ANNOTATION` token 类型，不是 Keyword。我的分类和编译器的真实分类一致。

---

## 抽象六：符（Symbol）— 「运算与结构的符号」

> 对应标准分类：**Operators**（运算符）+ **Delimiters**（分隔符）。标准分类里这是两种不同的 token，这里为初学合并为一类，子类中区分。
>
> **本质**：用符号替代英文单词来表示操作或划分结构。

### 子类一：运算符 — 「执行计算或比较」

| 符 | 含义 | 例子 |
|---|---|---|
| `=` | 赋值：把右边装进左边 | `speed = 50` |
| `:=` | 类型推断赋值：装进去同时自动推断型（仅用于 `var` 声明，不能用于普通赋值） | `var speed := 50`（自动推断为 int） |
| `+` `-` `*` `/` | 加减乘除 | `current_damage + damage` |
| `==` `!=` | 相等 / 不等 | `direction == Vector2.LEFT` |
| `<` `>` `<=` `>=` | 大小比较 | — |
| `&&` `\|\|` `!` | 且 / 或 / 非 | `currt_tool == AxeWood && use_tool()` |

### 子类二：分隔符 — 「划分代码结构」

| 符 | 含义 | 例子 |
|---|---|---|
| `:` | 类型标注开始 / 代码块开始 | `var x: int` / `if x:` |
| `->` | 返回值类型开始 | `-> Vector2` |
| `.` | 访问成员 | `player.velocity` |
| `$` | `get_node()` 的简写 | `$HitComponent` |
| `()` | 参数列表 / 调用执行 / 分组 | `movement_input()` |
| `[]` | 数组字面量 / 索引访问 | `[1, 2, 3]` / `arr[0]` |
| `{}` | 字典字面量 | `{"key": value}` |
| `,` | 参数分隔 | `connect("hurt", on_hurt)` |

### `$` 的设计哲学

Godot 知道你会频繁获取子节点引用，所以给了最短的写法：

```
$HitComponent  =  get_node("HitComponent")
```

它是一个名（`HitComponent`）被一个分隔符（`$`）修饰后的产物——结果是拿到那个节点实例的引用。

## 抽象七：释（Comment）— 「人类笔记」

> 对应标准分类：**Comments**（注释）
>
> **本质**：写给人看的，计算机会**完全跳过**。`#` 是注释的起始标记，从 `#` 到行尾的所有内容都是 释。

```gdscript
# 这是一行注释
print("hello")  # 行尾注释
```

## 一行代码里的全部七种抽象

```gdscript
@export var player_direction: Vector2 = Vector2.DOWN
```

| 片段 | 抽象类别 | 为什么 |
|---|---|---|
| `@export` | 注 | 给引擎看的元数据：「暴露到 Inspector，并允许场景覆盖值」 |
| `var` | 令（声明令） | 结构指令：「我要创建一个数据盒子」 |
| `player_direction` | 名（变量名） | 你给这个盒子取的标签 |
| `:` | 符（分隔符） | 「接下来是类型标注」 |
| `Vector2` | 型（内建复杂型） | 「这个盒子只能装 Vector2 形状的东西」 |
| `=` | 符（运算符） | 「把右边的値装进左边的盒子」 |
| `Vector2.DOWN` | 値（类常量） | 一个具体的、有名字的固定值：(0, 1) |

## 最容易混淆的三组区分

### 1. 名 vs 値

```gdscript
direction       ← 名（变量名，指向一个盒子）
"direction"     ← 値（字符串 "direction"，就是文本本身）
Vector2.LEFT    ← 値（类常量，是有名字的固定值，不是变量名）
```

**判定**：前面没有 `var` / `func` / `class_name` 等声明令来声明它，它就是値或者在引用一个名。有引号的一定是値。

### 2. 型 vs 名

```gdscript
class_name HitComponent    ← HitComponent 是 名（在贴标签）
var h: HitComponent        ← HitComponent 是 型（在描述形状）
```

**判定**：出现在 `:` 或 `->` 后面 → 型。其他位置 → 名。

### 3. 値 vs 型

```gdscript
var x = 5         ← 5 是値（一个具体的数字）
var x: int = 5    ← int 是型（描述形状：整数）
```

`int` 是型（描述「整数」这个概念），`5` 是値（一个具体的整数实例）。

## 附录：与 GDScript 编译器真实分类的对照

GDScript 编译器的词法分析器实际将代码切为以下 token 类型：

| 编译器 token 类型 | 本框架归类 |
| --- | --- |
| **Keyword**（`func` `var` `const` `class` `class_name` `extends` `signal` `enum` `static` `if` `elif` `else` `for` `while` `match` `break` `continue` `pass` `return` `as` `and` `or` `not` `is` `in` `await`） | 令 |
| **Annotation**（`@export` `@onready` `@tool` `@warning_ignore`…） | 注 |
| **Identifier**（用户定义的变量名/函数名/类型名） | 名 |
| **Built-in Type**（`int` `float` `bool` `String` `Vector2` `void`…） | 型 |
| **Built-in Pseudo**（`self` `true` `false` `null`） | 编译器视角是特殊标识符；本框架按语义把 `self` 归为 名（特殊名），`true`/`false`/`null` 归为 値 |
| **Literal: Number**（`1` `50` `0.3`） | 値 |
| **Literal: String**（`"walk_left"`） | 値 |
| **Constant**（`PI` `TAU` `NAN` `INF`） | 値 |
| **Operator**（`=` `:=` `+` `-` `*` `/` `==` `!=` `<` `>` `<=` `>=` `&&` `\|\|` `!`） | 符（运算符） |
| **Punctuation/Delimiter**（`:` `->` `.` `$` `()` `[]` `{}` `,` `;`） | 符（分隔符） |
| **Comment**（`# ...`） | 释 |
| **Newline / Indent / Dedent** | *（不可见，省略）* |

> 本框架和编译器分类的核心差异只有一处：编译器把 `int` 和 `player_direction` 都视为「标识符出现在不同上下文」，而我把「当标识符出现在类型位置时」单独提升为「型」——这是教学选择，不是错误。
